# 好吃不 Chewsy

一个给自己用的离线吃饭记录 App。

## 产品介绍

好吃不记录的不是“这道菜客观上好不好吃”，而是：

> 我去过哪家店，这次真实体验如何，下次还要不要去。

它帮助用户记住种草、观望和踩雷的经历，在再次决定去哪家店时，快速找到自己的历史记录，避免重复踩坑。

## 核心体验

1. 先选判词：种草、观望或踩雷。
2. 填写店名、菜名、理由、短评、图片和用餐时间。
3. 发布一条完整的到店记录。
4. 首页直接搜索店名或菜名，结果按店铺聚合。
5. 进入店铺查看历次到店记录，而不是接受系统替用户下结论。
6. 发现记错后可以编辑原记录，或永久删除。
7. 从已有的种草记录中随机抽取今晚吃什么。

## 记录规则

- 一顿饭对应一条记录。
- 一条记录属于一家店，可以包含多道菜。
- 店名必填，菜名和图片都可以不填。
- 一顿饭共用一个判词，菜名只记录本次吃过什么。
- 理由支持预设理由和自定义理由。
- 用餐时间默认当前时间，不允许选择未来时间。
- 所有数据保存在设备本地，不依赖网络服务。

## 当前功能

- SQLite 持久化记录、店铺、菜品、理由、草稿和图片元数据。
- Android 相机和相册入口。
- 应用私有目录保存原图和缩略图，并按图片哈希去重。
- 首页店铺搜索和菜名搜索。
- 店铺历史、记录详情、编辑和永久删除。
- 吃饭宇宙的历史浏览、判词筛选和本月筛选。
- 空种草记录时的盲抽空状态。
- 基础备份和导入页面。

导入导出、分享和战报图片不是当前产品主线，后续会继续简化和完善。

## 技术栈

- Flutter / Dart
- Drift + SQLite
- Riverpod
- `image_picker`：相机和相册
- `path_provider`：应用私有目录
- `archive`：本地备份归档

项目不接入地图、定位、云同步、统计 SDK 或在线搜索。

## 项目结构

```text
lib/
├── app/                    # 启动和运行时依赖
├── data/database/          # Drift 数据库和表
├── data/repositories/      # 记录和数据访问
├── domain/                 # 领域模型
├── features/               # 记录、宇宙、数据中心页面
└── services/               # 媒体和备份服务
```

## 本地开发

```bash
flutter pub get
flutter run
```

常用验证命令：

```bash
flutter analyze
flutter test
flutter build apk --debug
```

Debug 构建首次启动会注入示例记录；Release 构建首次启动为空。
